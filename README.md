# 360-workflow

Оценка 360° — веб-приложение для оценки сотрудников: самооценка, руководитель, коллеги, подчинённые, клиенты и партнёры. Администратор заводит участников, назначает оценки и скачивает результаты в Excel. Участники заполняют анкеты, ответы сохраняются по ходу заполнения.

Приложение работает на Python ≥ 3.10 без внешних зависимостей. Вход по собственным логинам и паролям; связь с Битрикс24 используется для задач и напоминаний. Данные хранятся в `data/360.sqlite`.

## Запуск на Windows

1. Откройте `run.bat`. Если Python отсутствует, скрипт скачает портативный Python 3.12.10 для Windows x64 в `python/`. При первом запуске также создаётся `config.json` из примера.
2. Остановите сервер сочетанием Ctrl+C и создайте первого администратора:

   ```powershell
   .\start.ps1 create-admin nat
   ```

   Введите ФИО и пароль, затем снова откройте `run.bat`. Если политика PowerShell запрещает запуск скрипта, используйте `run.bat create-admin nat`.
3. Войдите на [http://localhost:8082](http://localhost:8082), добавьте участников и назначьте оценку.

Окно запуска должно оставаться открытым. С установленным Python те же команды доступны напрямую:

```text
python manage.py run
python manage.py create-admin ЛОГИН
python manage.py password ЛОГИН
python manage.py check
```

Участник видит только свои незаполненные анкеты. По каждому утверждению нужно выбрать 1–5; комментарии и семь открытых вопросов необязательны. Кнопка отправки доступна после сохранения. При обрыве связи несохранённые ответы остаются в открытой вкладке: нажмите «Повторить сохранение». При истечении сессии войдите снова под тем же логином; приложение вернёт вас к анкете. Перед закрытием вкладки дождитесь надписи «Сохранено».

Для обычного сотрудника в анкете 50 утверждений; для руководителя — 54. После отправки менять ответы может только сам участник после возврата анкеты администратором. Срок служит ориентиром: анкета доступна, пока администратор не завершил или не отменил оценку.

## Настройки config.json

Файл не попадает в Git. Не передавайте адрес вебхука через чат и не публикуйте его.

| Поле | Значение |
|---|---|
| `timezone` | Часовой пояс процесса на Linux, например `Asia/Yekaterinburg`. Пусто — системный пояс; на Windows используется пояс системы. |
| `server.host` | Адрес прослушивания, по умолчанию `127.0.0.1`. |
| `server.port` | Локальный порт приложения, по умолчанию `8082`. |
| `server.public_url` | Адрес для участников; включается в задачи Битрикс24. |
| `server.secure_cookie` | `true` для публичного HTTPS, `false` для локального HTTP. |
| `server.trust_proxy` | `true` за локальным обратным прокси: учитывать адрес клиента из `X-Forwarded-For`. |
| `server.session_hours` | Срок сессии в часах, по умолчанию `12`. |
| `server.open_browser` | Открывать браузер при запуске; для службы или автозагрузки — `false`. |
| `bitrix24.webhook` | Входящий вебхук от имени Натальи с правами **task** и **user**. Пусто — приложение работает без задач Битрикс24. |
| `bitrix24.verify_ssl` | Проверять сертификат портала, по умолчанию `true`. |
| `reminder_days` | Дни напоминаний после выдачи анкеты, по умолчанию `[7, 12]`. |
| `default_deadline_days` | Срок новой оценки в днях от сегодня, по умолчанию `14`. |

Вебхук: Битрикс24 → Разработчикам → Другое → Входящий вебхук. Проверка подключения: `run.bat check` или `python manage.py check`. В карточке участника выберите сотрудника портала. Для внешних участников оставьте связь пустой и сообщите им об анкете самостоятельно.

Задачи создаются и закрываются через очередь в базе. Ошибки видны в карточке оценки; «Повторить» возобновляет попытки. При возврате на доработку открывается прежняя задача. Фоновый поток проверяет напоминания и повторяет операции раз в час.

## Офисный ПК, вход через VPS

```text
Участник → HTTPS 360.transtehcom.ru:8443 → Caddy на VPS → 127.0.0.1:18082
                                                               ↑ SSH-туннель
Офисный ПК: приложение на 127.0.0.1:8082 ─────────────────────────┘
```

На VPS:

1. Создайте DNS A-запись `360.transtehcom.ru`, указывающую на IP VPS. Разрешите входящие TCP 80 для сертификата и 8443 для приложения.
2. В существующем блоке `Match User kpitunnel` файла `/etc/ssh/sshd_config` **добавьте** `127.0.0.1:18082` к значениям `PermitListen`, сохранив ранее разрешённые порты. Проверьте `sudo sshd -t`, затем `sudo systemctl reload ssh`.
3. В `deploy/Caddyfile` замените `DOMAIN` на `360.transtehcom.ru:8443`, `PORT` на `18082`. **Допишите блок в существующий `/etc/caddy/Caddyfile`, не заменяйте файл: там уже может быть сайт `kpi.transtehcom.ru:8443`.** Первую строку блока `# 360-workflow: …` сохраните: по ней `install.sh` определяет, что сайт уже добавлен. Допустим также `import` отдельного файла.
4. Выполните `sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` и `sudo systemctl reload caddy`.

На офисном ПК:

1. Проверьте ручной запуск приложения и наличие администратора. В `config.json` задайте `host: "127.0.0.1"`, `port: 8082`, `public_url: "https://360.transtehcom.ru:8443"`, `secure_cookie: true`, `trust_proxy: true`, `open_browser: false`. При `secure_cookie: true` вход выполняется через HTTPS, локальный HTTP не сохраняет сессию.
2. Для туннеля используется существующий ключ `%USERPROFILE%\.ssh\kpi_tunnel_ed25519` и пользователь `kpitunnel`. Один раз подключитесь `ssh -i "$env:USERPROFILE\.ssh\kpi_tunnel_ed25519" kpitunnel@2.26.103.191`, сверив отпечаток VPS. Это запишет проверенный ключ сервера в `known_hosts`; отказ интерактивного shell у пользователя туннеля допустим.
3. Остановите ручной экземпляр приложения. Запустите автозагрузчик:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\office-autostart.ps1
   ```

   При другом VPS или ключе передайте `-Vps`, `-Key`, `-TunnelUser`. Порт туннеля по умолчанию — `18082`.
4. Создайте `360-workflow.cmd` в папке автозагрузки Windows (`Win+R` → `shell:startup`), заменив путь на расположение проекта:

   ```bat
   @echo off
   start "" /min powershell -NoProfile -ExecutionPolicy Bypass -File "C:\path\360-workflow\deploy\windows\office-autostart.ps1"
   ```

Скрипт перезапускает приложение и туннель при сбоях; второй экземпляр блокируется mutex. Журналы: `data/office-autostart.log`, `data/app.out.log`, `data/app.err.log`, `data/tunnel.err.log`. Компьютер должен быть включён и не уходить в сон. При недоступном туннеле Caddy показывает сообщение «временно недоступна».

## Переезд на Ubuntu

На Ubuntu 22.04 или новее установите Git и клонируйте проект в `/opt/360-workflow`:

```bash
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/Transtehcom/360-workflow.git /opt/360-workflow
```

Для переноса данных сначала остановите старое приложение. Скопируйте `config.json` в `/opt/360-workflow/` и `data/360.sqlite` в `/opt/360-workflow/data/` нового сервера **до запуска установщика**; если служба уже работает — сначала остановите её: `sudo systemctl stop 360-workflow`. Установщик назначит права на базу. Без `config.json` он создаст его из примера. Затем запустите установщик от root:

```bash
cd /opt/360-workflow
sudo bash deploy/install.sh 360.transtehcom.ru 8443
sudo -u s360 python3 manage.py create-admin nat
```

Установщик ставит Python, SQLite и Caddy (при необходимости из официального репозитория Caddy), создаёт пользователя `s360`, обновляет настройки для HTTPS и добавляет сайт к существующему Caddyfile с предварительной проверкой и копией `Caddyfile.before-360`. Если сайт уже есть, блок сохраняется: при переезде **замените в нём порт туннеля `18082` на локальный порт `8082` вручную** (установщик напомнит об этом предупреждением), проверьте конфигурацию и перезагрузите Caddy. При смене домена или порта обновите существующий блок вручную. Исходный `config.json` один раз сохраняется как `config.json.before-install`. Повторный запуск установщика обновляет код через `git pull --ff-only` и перезапускает службу.

Журнал: `journalctl -u 360-workflow -f`. Остановка: `sudo systemctl stop 360-workflow`. Код и настройки для службы доступны только для чтения; записи разрешены в `/opt/360-workflow/data`.

## Выгрузка и резервные копии

«Итоги .xlsx» доступны для любой оценки и включают только отправленные анкеты. В файле три листа: сводная таблица, открытые вопросы, комментарии. Средние и разрыв с самооценкой рассчитаны формулами Excel и пересчитываются после правки значений.

Для ручной копии остановите приложение и скопируйте `data/360.sqlite`; сохраните также `config.json` отдельно. Чтобы снять копию работающей базы, используйте SQLite backup API, а не копирование файла:

```bash
sqlite3 data/360.sqlite ".backup '360-backup.sqlite'"
```

На Ubuntu установщик создаёт ежедневную копию в `/var/backups/360-workflow`, хранит её 14 дней. Для восстановления остановите службу, замените базу, назначьте владельца `s360:s360` и запустите службу.

## Проверки

```text
python -m unittest discover tests
node --test tests/test_autosave.cjs
```

Node нужен только для тестов очереди сохранения; приложению он не требуется. HTTP-тесты работают с отдельной базой в памяти и без обращения к порталу.

Для ручной проверки интерфейса с вымышленными участниками и отдельной базой:

```text
python tests/preview_server.py --port 8083
```

Сервер доступен только на `127.0.0.1:8083`, Битрикс24 отключён. Логины: `preview-admin` и `preview-user`; пароль обоих — `preview360`. База временная и удаляется при остановке. Основная база и конфигурация не изменяются.
