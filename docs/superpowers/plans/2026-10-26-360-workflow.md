**Goal:** Отдельное веб-приложение «Оценка 360°»: Наталья заводит участников, назначает оценки, ставит задачи в Битрикс24, а участники заполняют анкету. Итог выгружается в .xlsx по шаблону заказчика.

**Architecture:** Один процесс Python. Состав:
- `ThreadingHTTPServer` отдаёт JSON API и статический интерфейс из `web/`;
- одно соединение SQLite под общей `RLock`, как в KPI-дашборде;
- всё, что уходит в Битрикс24, сначала пишется в таблицу-очередь `b24_ops`; фоновый поток выполняет её вне блокировки базы, поэтому сбои портала не мешают работе;
- `.xlsx` собирается вручную через `zipfile` и XML.

**Tech Stack:** Python ≥ 3.10, только стандартная библиотека (`http.server`, `sqlite3`, `urllib`, `zipfile`, `xml.sax.saxutils`), `unittest`. Интерфейс на чистом HTML/CSS/JS без сборки.

**Spec:** `docs/superpowers/specs/2026-10-26-360-workflow-design.md` — читать вместе с планом. Содержание анкеты (54 утверждения, короткие названия, тексты, открытые вопросы) переносится в код **дословно из спецификации**, раздел «Содержание анкеты».

## Global Constraints

- Только стандартная библиотека Python. Ни `openpyxl`, ни других зависимостей: на офисном ПК работает встраиваемый Python из `start.ps1`.
- Python ≥ 3.10. Проверка — как в `start.ps1` дашборда.
- Тексты интерфейса, сообщения об ошибках, комментарии в коде и сообщения коммитов — на русском, как в дашборде. Имена в коде — английские.
- `config.json` и `data/` — в `.gitignore`. Адрес вебхука в git не попадает.
- База — `data/360.sqlite`. Порт по умолчанию — `8082`. Публичный адрес — `https://360.transtehcom.ru:8443`. Порт туннеля на VPS — `18082`.
- Пароль — PBKDF2-SHA256, 200 000 итераций, соль 16 байт hex. Минимальная длина — 6 символов.
- Защита от подбора: не больше 10 неудачных попыток за 15 минут на пару (IP, логин).
- Сессия — 12 часов (`server.session_hours`). Cookie `s360_session; HttpOnly; SameSite=Lax; Path=/`, плюс `; Secure`, если `server.secure_cookie`.
- Роли оценивающих, ключи и подписи (порядок колонок в выгрузке):
  - `self` — «самооценка»;
  - `manager` — «руководитель»;
  - `peer` — «коллега»;
  - `report` — «подчинённый»;
  - `client` — «клиент/партнёр».
- Шкала — целые 1–5. Тексты ответов (комментарии, открытые вопросы) — не длиннее 5000 символов.
- Напоминания — `reminder_days` [7, 12]. Срок по умолчанию — `default_deadline_days` 14.
- Права вебхука — только `task` и `user`. Методы Битрикс24 — только эти:
  - `user.get`;
  - `tasks.task.add`, `tasks.task.list`, `tasks.task.update`, `tasks.task.complete`, `tasks.task.renew`;
  - `task.commentitem.add`;
  - `profile` — только для `manage.py check`.
- Тесты запускаются командой `python -m unittest discover tests` из корня репозитория. Каждый тестовый модуль начинается с `sys.path.insert` корня, как `tests/test_employees.py` дашборда. База в тестах — `connect(":memory:")`.

## Review Focus

1. **Текст ответа с управляющими символами** (`\x0b`, `\x00`), эмодзи, переводами строк или начинающийся с `=`. Ожидается: `.xlsx` открывается, текст остаётся текстом, а не формулой. Тест — в Task 5.
2. **Двойное нажатие «Отправить», вторая вкладка.** Ответ после отправки анкеты или после завершения оценки. Ожидается: 409, сохранённое не меняется, задача закрывается один раз. Тест — в Task 4.
3. **Сессия истекла посреди анкеты.** Ожидается: сохранение отвечает 401, уже сохранённые ответы на месте, после повторного входа участник продолжает с того же блока. Тест — в Task 8, поведение интерфейса — в Task 9.
4. **Битрикс24 создал задачу, но ответ не дошёл** (таймаут). Ожидается: при повторе вторая задача не создаётся. Тест — в Task 7.
5. **Выгрузка без единой отправленной анкеты; ФИО с кириллицей и кавычками в имени файла.** Ожидается: файл скачивается и открывается, формул с делением на ноль нет. Тест — в Task 6 и Task 8.

**Схема базы** (вся — в `app/common.py: SCHEMA`; меняется только в той задаче, где это сказано):

```sql
CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, fio TEXT NOT NULL, position TEXT NOT NULL DEFAULT '',
  login TEXT NOT NULL UNIQUE, pwd_hash TEXT NOT NULL, salt TEXT NOT NULL, is_admin INTEGER NOT NULL DEFAULT 0,
  active INTEGER NOT NULL DEFAULT 1, b24_user_id INTEGER, created_at TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS sessions (token TEXT PRIMARY KEY, user_id INTEGER NOT NULL, expires TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS assessments (id INTEGER PRIMARY KEY, subject_id INTEGER NOT NULL, is_manager INTEGER NOT NULL,
  deadline TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'active', created_by INTEGER NOT NULL, created_at TEXT NOT NULL,
  closed_at TEXT);                                   -- status: active | finished | cancelled
CREATE TABLE IF NOT EXISTS assignments (id INTEGER PRIMARY KEY, assessment_id INTEGER NOT NULL, user_id INTEGER NOT NULL,
  role TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'draft', sent_at TEXT NOT NULL, submitted_at TEXT,
  returned_at TEXT, b24_task_id INTEGER, UNIQUE (assessment_id, user_id));
                                                     -- status: draft | submitted | closed
CREATE TABLE IF NOT EXISTS answers (assignment_id INTEGER NOT NULL, key TEXT NOT NULL, value TEXT NOT NULL,
  updated_at TEXT NOT NULL, PRIMARY KEY (assignment_id, key));
CREATE TABLE IF NOT EXISTS b24_ops (id INTEGER PRIMARY KEY, assignment_id INTEGER NOT NULL, op TEXT NOT NULL,
  payload TEXT NOT NULL DEFAULT '{}', attempts INTEGER NOT NULL DEFAULT 0, last_error TEXT, done_at TEXT,
  created_at TEXT NOT NULL);                         -- op: create | deadline | comment | complete | renew
CREATE TABLE IF NOT EXISTS reminders (assignment_id INTEGER NOT NULL, day INTEGER NOT NULL, sent_at TEXT NOT NULL,
  PRIMARY KEY (assignment_id, day));
```

**Ключи ответов** (`answers.key`):
- утверждения — `A1`…`M4`, значение `"1"`…`"5"`;
- комментарий блока — `c:A`…`c:M`;
- открытые вопросы — `O1`…`O7`;
- дополнительные комментарии — `extra`.

Пустая строка или `null` удаляет ответ.

**Ошибки домена** — общие для `users.py` и `assessments.py`, определены в `app/common.py`:
- `class BadRequest(Exception)` → HTTP 400;
- `class Forbidden(Exception)` → 403;
- `class NotFound(Exception)` → 404;
- `class Conflict(Exception)` → 409.

Текст исключения — готовое сообщение для пользователя на русском.

    1. Под `lock` выбирает невыполненные операции с `attempts < 24` по возрастанию `id`.
    2. Для каждой анкеты выполняет только первую по порядку: следующие ждут, пока выполнится предыдущая.
    3. Вызовы Битрикс24 — **вне** `lock`.
    4. `create`:
       - анкеты уже нет (убрали) — выполнено без вызова;
       - у анкеты уже есть `b24_task_id` — выполнено;
       - иначе `find_task(…)`, и только если задачи нет — `add_task`; ответственный, ФИО оцениваемого и срок берутся из базы на момент выполнения;
       - полученный ID под `lock` записывается в `assignments.b24_task_id`. Если за время вызова анкету убрали, задача сразу закрывается (`complete`), чтобы не висела.
    5. Остальные операции: `task_id` = `payload["task_id"]`, иначе `assignments.b24_task_id`.
       - если `task_id` нет, а по анкете есть невыполненный `create` (с любым числом попыток), операция ждёт и попыткой не считается;
       - если нет ни `task_id`, ни `create`, операция выполнена без вызова.
    6. Ошибка `B24Error` → `attempts += 1`, `last_error = str(e)[:300]`, операция остаётся.
  - `retry(con, assignment_id) -> None` — обнуляет `attempts` и `last_error` у невыполненных операций анкеты (кнопка «Повторить»).
  - `class Worker(app)` — поток-демон:
    - `start()`;
    - `wake()` — `threading.Event` для немедленного прохода после действий в интерфейсе;
    - цикл: `due_reminders` раз в час, затем `process`, ожидание `event.wait(3600)`.

    Не запускается, если `bitrix24.webhook` пуст. Исключения пишутся в журнал (`traceback.print_exc`) и не останавливают поток.
