# Оценка 360° — описание приложения

Дата: 26.10.2026. Репозиторий: `Transtehcom/360-workflow`.

Пометка **[решение Claude]** — решение принял исполнитель, заказчик его не обсуждал; при чтении его можно поменять. Всё без пометки согласовано с заказчиком.

## Зачем

HR-сотрудник, Новоселецкая Наталья, проводит оценку 360° по опроснику компании (54 утверждения по шкале 1–5 и открытые вопросы). Сейчас анкета существует в виде Word-документа, а итоги сводятся вручную в Excel-шаблон «Оценка 360 градусов.xlsx».

Нужно отдельное веб-приложение, в котором Наталья:

1. заводит учётные записи участников и сама раздаёт им логины и пароли;
2. назначает оценку: кого оцениваем и кто оценивает;
3. автоматически ставит оценивающим задачу в Битрикс24 со ссылкой на анкету;
4. скачивает итог в виде .xlsx в формате своего шаблона и дальше обрабатывает его сама.

Оценивающие входят в приложение под выданным логином, видят свои анкеты, заполняют их, и после этого у них остаётся надпись «Оценивать больше некого» и кнопка «Выйти».

**Признак успеха:** Наталья проводит оценку от назначения до готового .xlsx, ничего не перенося руками, а оценивающие заполняют анкету без инструкций.

## Цели

- Учётные записи внутри приложения: логин и пароль задаёт Наталья. С учётной записью Битрикс24 вход не связан.
- Назначение оценки и рассылка задач в Битрикс24.
- Анкета с сохранением по ходу заполнения.
- Выгрузка .xlsx по каждой оценке.
- Размещение на `https://360.transtehcom.ru:8443` по той же схеме, что KPI-дашборд.

## Не цели

- Интеграция с KPI-дашбордом. Это **отдельное приложение с отдельной задачей**: свой репозиторий, своя база, свои учётные записи, свой процесс. Общий у них только подход к стеку.
- Вход через Битрикс24 (OAuth, единые учётные записи).
- Анонимность. Итоги видит Наталья, и это допустимо, как и доступ администраторов сервера к базе. Шифрование ответов не нужно.
- Отчёты и графики на экране (паутинка, gap-анализ, интерпретация по шкале). Наталья делает это сама на основе .xlsx. **[решение Claude]** В файл добавляются только средняя и разрыв с самооценкой (см. «Выгрузка .xlsx»).
- Рассылка писем: оповещение идёт только через задачи Битрикс24.

## Чего нельзя допустить (провал, даже если всё «работает»)

- Оценивающий видит чужие ответы или итоги.
- Ответы теряются: закрыли вкладку, кончилась сессия, перезапустили сервер.
- Выгруженный файл не открывается в Excel или ломает структуру шаблона, к которой привыкла Наталья.
- Задачи в Битрикс24 дублируются: на одну анкету больше одной задачи.

## Роли и доступ

- **Администратор** — Наталья. **[решение Claude]** Администраторов может быть несколько (флаг у учётной записи), права у всех одинаковые. Первого администратора создаёт команда `python manage.py create-admin ЛОГИН` (как `manage.py password` в дашборде).
- **Участник** — любой, кому Наталья завела учётную запись: сотрудник компании или внешний человек (клиент, партнёр). Видит только назначенные ему анкеты и только пока их заполняет. Отправленную анкету не видит и изменить не может.
- **[решение Claude]** Если администратору назначили анкету, после входа он видит свой раздел администратора и над ним блок «Мои анкеты».

## Экраны

Наброски (черновые) показаны заказчику; ниже описано, что на них должно быть. Интерфейс на русском и должен работать на телефоне, потому что оценивающие могут заполнять анкету не за компьютером **[решение Claude]**.

### 1. Вход
Логин, пароль, «Войти». Один экран для всех.

### 2. Администратор: оценки
Вверху справа ФИО и «Выйти». Разделы: «Оценки» и «Участники».

**Новая оценка:**
- **Кого оцениваем** — выбор из участников.
- **«Оценивается как руководитель»** — флажок. Если включён, в анкете есть блок M «Управленческие качества», иначе блока нет ни в анкете, ни в выгрузке **[решение Claude]**.
- **Кто оценивает** — список строк «участник + роль». Роли: самооценка, руководитель, коллега, подчинённый, клиент/партнёр (из опросника). Оцениваемый добавляется сам с ролью «самооценка», Наталья может его убрать **[решение Claude]**. Один участник встречается в оценке один раз.
- **Срок** — по умолчанию сегодня + 14 дней (опросник: «рассылка анкеты: 2 недели»).
- **«Разослать»** — создаёт анкеты и ставит задачи в Битрикс24.

**Список оценок:** оцениваемый, срок, «заполнили N из M», статус. Действия:
- **«Итоги .xlsx»** — доступно в любой момент; в файл попадают только отправленные анкеты.
- **«Открыть»** — карточка оценки: кто заполнил, кто нет, у кого задача в Битрикс24 не поставилась. Отсюда можно:
  - добавить или убрать оценивающего;
  - поменять срок (срок задач в Битрикс24 меняется тоже);
  - повторить постановку задачи;
  - **«Завершить»** — незаполненные анкеты закрываются и исчезают у оценивающих;
  - **«Отменить»**.

Отправленную анкету Наталья может открыть на просмотр и **вернуть оценивающему на доработку** **[решение Claude]**. Вернуть можно, только пока оценка идёт. Анкета снова появляется у оценивающего с сохранёнными ответами, а его задача в Битрикс24 переоткрывается (см. «Битрикс24»).

**[решение Claude]** Убрать из оценки можно только того, кто ещё не отправил анкету. Его черновик удаляется вместе с ним. Отправившего убрать нельзя: если его ответы не нужны, Наталья удаляет колонку в выгруженном файле. Поэтому «N из M» и выгрузка всегда считаются по оставшимся в оценке.

**[решение Claude]** Статусы оценки: «идёт», «завершена», «отменена». Удалять оценки нельзя, только отменять.

### 3. Администратор: участники
Таблица: ФИО, должность, логин, связь с Битрикс24, администратор, активен.

Карточка участника:
- ФИО, должность **[решение Claude]**, логин, пароль (задаёт Наталья; при правке — «сбросить пароль»).
- **Сотрудник в Битрикс24** — выбор из активных пользователей портала (`user.get`). Поле можно оставить пустым, например для внешних людей. Тогда задача не ставится, и Наталья сама сообщает человеку, что пора заполнить анкету.
- Флажки «Администратор», «Активен».

Участника с ответами удалить нельзя, только отключить. Отключённый не может войти **[решение Claude]**.

**[решение Claude]** Сменить свой пароль участник не может: это делает Наталья. Так проще и соответствует «Наталья придумала логины и пароли и раздала».

### 4. Участник: мои анкеты
Карточки «Оценить: ФИО» → «вы — коллега · до 06.11.2026», для начатых анкет — «заполнено N блоков из M». Кнопка «Начать» или «Продолжить».

Анкеты завершённых и отменённых оценок не показываются. **[решение Claude]** Анкету можно заполнить и после срока, пока Наталья не завершила оценку.

### 5. Анкета
- Блоки по одному на экран, вверху лента блоков (A, B, C… «Открытые вопросы»), «Назад» / «Дальше».
- Над каждым блоком — подсказка со шкалой (тексты из опросника, ниже).
- Каждое утверждение — пять кнопок 1–5. Под блоком — поле «Комментарий / примеры».
- Каждое изменение сохраняется на сервере сразу, без кнопки «Сохранить». Можно выйти и продолжить позже, в том числе с другого устройства.
- Последний экран — открытые вопросы и поле «Дополнительные комментарии», затем «Отправить».
- **[решение Claude]** Все утверждения по шкале обязательны: «Отправить» не сработает, пока есть пропуски, и покажет, в каком блоке. Варианта «не могу оценить» нет — его нет в опроснике. Комментарии и открытые вопросы необязательны.
- После отправки анкета исчезает из списка, а задача в Битрикс24 закрывается.

### 6. Участник: всё сделано
«Оценивать больше некого» и «Выйти» вверху справа. Тот же экран видит участник, у которого анкет не было вообще.

## Содержание анкеты

Шкала (показывается подсказкой над каждым блоком):
- 1 — Никогда / Совершенно не проявляет (требуется немедленное развитие)
- 2 — Редко / Проявляет недостаточно (ниже ожиданий)
- 3 — Иногда / Соответствует базовым ожиданиям
- 4 — Часто / Выше ожиданий (сильная сторона)
- 5 — Постоянно / Выдающееся проявление (лидер, образец)

Инструкция респонденту: «Для каждого утверждения отметьте, насколько вы согласны с ним применительно к оцениваемому сотруднику по шкале 1–5. В поле „Комментарий“ приводите примеры, если возможно».

Ниже по каждому утверждению: краткое название (это строка «Индикатор» в выгрузке, взято из шаблона .xlsx) — полный текст (из опросника). Названия блоков в выгрузке — из шаблона, в анкете — из опросника.

**A. Бизнес-мышление** (в выгрузке «Бизнес-мышление»)
1. Понимание бизнес-показателей — Понимает значение ключевых бизнес-показателей и использует их в работе.
2. Прогноз изменений — Прогнозирует изменения в профессиональной сфере и предлагает подходы для развития бизнеса.
3. Погружение — Быстро погружается в детали нового направления.
4. Альтернативные решения — Предлагает альтернативные и эффективные решения задач.
5. Возможности роста — Выявляет возможности для роста компании, увеличения доходов и оптимизации расходов.

**B. Коммуникативные навыки** («Коммуникативные навыки»)
1. Четкие мысли — Чётко формулирует и излагает свои мысли.
2. Стиль коммуникации — Адаптирует стиль коммуникации под потребности собеседника.
3. Аргументация — Аргументирует свою точку зрения, опираясь на факты и данные.
4. Взаимодействие — Быстро налаживает взаимодействие с новыми коллегами.
5. Внимание — Внимательно слушает собеседника.

**C. Готовность к изменениям** («Готовность к изменениям»)
1. Адаптивность — Легко адаптируется к изменениям в ситуации и на рынке.
2. Преимущества — Находит преимущества изменений и доносит их до коллег.
3. Внедрение — Прилагает усилия для внедрения новых подходов.
4. Реализация — Стремится к улучшениям и реализует предложенные изменения.
5. Создание условий — Создаёт условия для команды, чтобы гибко внедрять нововведения.

**D. Клиентоориентированность** («Клиентоориентированность»)
1. Решение задач — Находит способы решения задач клиента и стремится превосходить ожидания.
2. Рекомендации — Становится экспертом по клиенту, анализирует его задачи и даёт рекомендации.
3. Обратная связь — Собирает обратную связь о продукте и использует её для улучшений.
4. Активное слушание — Внимательно слушает клиента и задаёт правильные вопросы.
5. Мнение клиента — Смотрит на задачу с точки зрения клиента и учитывает его мнение.

**E. Работа с искусственным интеллектом (ИИ)** («Искусственный интеллект»)
1. Возможности — Понимает возможности и ограничения современных ИИ-технологий.
2. Подбор инструментов — Подбирает подходящие ИИ-инструменты для рабочих задач.
3. Оценка — Проверяет и критически оценивает результаты ИИ перед использованием.
4. Интеграция — Интегрирует ИИ-решения в рабочие процессы для повышения эффективности.
5. Тенденции — Следит за тенденциями в сфере ИИ и адаптирует свою работу.

**F. Стрессоустойчивость** («Стрессоустойчивость»)
1. Логика — Действует логично и последовательно в проблемных ситуациях.
2. Восстановление — Быстро восстанавливается и продолжает работу над задачей.
3. Позитив — Поддерживает позитивный настрой и укрепляет коллег.
4. Многозадачность — Эффективно работает в условиях многозадачности и нехватки информации.
5. Объем работы — Справляется с большим объёмом работы без потери качества.

**G. Эффективность и результат** («Эффективность и результат»)
1. Результаты — Достигает высоких результатов в своих ключевых задачах.
2. Система — Системно организует своё время и ресурсы для достижения целей.

4. Завершение задач — Доводит начатые задачи до завершения, обеспечивает качество.
5. Оценка — Оценивает и улучшает собственные рабочие процессы.

**H. Взаимодействие** («Взаимодействие»)
1. Конструктивность — Проявляет себя конструктивно при взаимодействии с коллегами.
2. Результативность — Знает, в каких ситуациях его коммуникация наиболее результативна.
3. Изменения — Готов менять подход в общении при необходимости.
4. Обратная связь — Позитивно реагирует на обратную связь и учитывает её. *(В шаблоне .xlsx этой строки нет — добавлена **[решение Claude]**.)*

**I. Развитие и потенциал** («Развитие и потенциал»)

4. Амбиции — Проявляет амбиции и готовность переходить на следующий уровень.

**K. Профессиональное развитие** («Профессиональное развитие»)

2. Управление временем — Эффективно управляет временем и приоритетами.

**Открытые вопросы** (порядок как на листе «Открытые вопросы» шаблона):
1. Приведите пример ситуации, когда сотрудник проявил себя с лучшей стороны.
2. Приведите пример ситуации, когда сотрудник мог бы действовать иначе.
3. Как сотрудник ведёт себя в стрессовых или сложных ситуациях?
4. Какие действия сотрудника особенно ценны для команды?
5. В чём, на ваш взгляд, заключаются главные профессиональные способности и сильные стороны сотрудника?
6. На что важно обратить внимание и скорректировать? Что необходимо развивать или делать иначе?

Плюс поле «Дополнительные комментарии» (из приложения к опроснику).

**[решение Claude]** Анкета одинакова для всех ролей, в том числе для самооценки (текст в третьем лице не меняется). Содержание анкеты хранится в коде как данные, а не в базе: правка вопросов — правка кода. Отправленные анкеты хранят ответы по ключам утверждений (например `H4`), так что добавление новых вопросов не ломает старые оценки.

## Выгрузка .xlsx

Один файл на оценку: `Оценка 360 — ФИО — ДД.ММ.ГГГГ.xlsx`. Структура повторяет шаблон заказчика `docs/template/Оценка 360 градусов.xlsx` (копия лежит в репозитории как образец; данных в нём нет, только структура).

**Как устроен шаблон** (с ним сверяются тесты выгрузки):
- **Листы и их порядок:** «Сводная таблица», «Открытые вопросы». Других листов нет.
- **Строки 1–2** пустые, колонка A на первом листе пустая. Таблица начинается с B3. Объединённых ячеек нет.
- **Шрифт** Calibri 11. Шапка (строка 3) — жирный 12 пт, цвет `#44546A`, по центру или слева, перенос по словам.
- **Строки-заголовки компетенций** — жирный шрифт, заливка `#E4EEDB`.
- **Строки индикаторов** — обычный шрифт.

## Битрикс24

**Вебхук.** Входящий вебхук создан под учётной записью Натальи с правами «Задачи» (`task`) и «Пользователи» (`user`). Задачи ставятся от её имени. Адрес хранится только в локальном `config.json`, который не попадает в git.

**Методы:**
- `user.get` — список активных пользователей для выбора в карточке участника. **[решение Claude]** Список кешируется на 10 минут и обновляется кнопкой.
- `tasks.task.add` — при рассылке, по одной задаче на анкету, если у оценивающего есть связь с Битрикс24:
  - название — «Оценка 360°: ФИО оцениваемого»;
  - ответственный — оценивающий;
  - крайний срок — срок оценки;
  - в описании — ссылка `https://360.transtehcom.ru:8443` и фраза «войдите под логином, который выдала Наталья»;
  - ID задачи хранится у анкеты.
- `tasks.task.update` — при смене срока.
- `tasks.task.complete` — когда анкета отправлена, а также при завершении или отмене оценки и удалении оценивающего. **[решение Claude]** Задачи не удаляются, только закрываются, с комментарием о причине при отмене.
- `tasks.task.renew` — когда Наталья возвращает анкету на доработку: та же задача переоткрывается, и в неё пишется комментарий «Анкета возвращена на доработку». Новая задача не создаётся **[решение Claude]**.
- `task.commentitem.add` — напоминания и комментарии о причине закрытия.

Все эти методы входят в право «Задачи» (`task`), других прав не нужно.

**Напоминания.** На 7-й и 12-й день после рассылки (из опросника) — комментарий в задаче «Напоминание: анкета по ФИО ещё не заполнена, срок — ДД.ММ». Комментарий пишется только тем, кто не отправил анкету. **[решение Claude]** Механизм: фоновый поток в приложении раз в час проверяет, кому пора напомнить, и отмечает отправленные напоминания в базе, чтобы не продублировать. Дни напоминаний задаются в `config.json`.

**Сбои Битрикс24 не блокируют работу.**
- Анкета создаётся всегда. Если задача не поставилась, в карточке оценки видно «задача не поставлена» и кнопку «Повторить».
- Закрытие задачи после отправки и напоминания при сбое повторяются фоновым потоком.
- Повтор не создаёт вторую задачу: если ID задачи уже есть, новая не ставится.

## Как сделано

**Стек — по образцу KPI-дашборда (согласовано: заимствовать подход, не интегрировать):**
- Python 3 только со стандартной библиотекой: `http.server.ThreadingHTTPServer`, `sqlite3`, `urllib`.
- Одна SQLite-база `data/360.sqlite`.
- Веб-интерфейс — статические файлы в `web/` без сборки.
- Тесты — `unittest`.
- Код из дашборда **копируется и адаптируется**, а не импортируется: вход с PBKDF2-хешами, защита от подбора пароля (10 попыток за 15 минут), сессии в базе, cookie `HttpOnly; SameSite=Lax` (+ `Secure` за HTTPS), учёт `X-Forwarded-For` за прокси, клиент вебхука Битрикс24 с повтором при сетевых сбоях.
- `.xlsx` пишется стандартной библиотекой (`zipfile` + XML), без `openpyxl` **[решение Claude]**: у дашборда нет внешних зависимостей, и на офисном ПК он работает на встраиваемом Python.

**Настройки** — `config.json` (в `.gitignore`, образец `config.example.json`):
- `server`: `host`, `port` (по умолчанию 8082, у дашборда 8081), `public_url`, `secure_cookie`, `trust_proxy`, `session_hours`;
- `bitrix24`: `webhook`, `verify_ssl`;
- `reminder_days` [7, 12];
- `default_deadline_days` 14.

`data/` тоже в `.gitignore`.

**Размещение сейчас** — офисный ПК по схеме дашборда (README дашборда, раздел «Дашборд в офисе, вход через VPS»):
```
Участник ──HTTPS──► VPS: Caddy (360.transtehcom.ru:8443) ──► 127.0.0.1:18082
                                   ▲ SSH-туннель (открывает офис)
Офис: приложение 127.0.0.1:8082 ───┘    ──► Битрикс24
```
- DNS: A-запись `360.transtehcom.ru` на IP VPS.
- Caddy на VPS: отдельный блок сайта `360.transtehcom.ru:8443` с `reverse_proxy 127.0.0.1:18082` и страницей «временно недоступен». Блок дашборда не трогать.
- SSH: пользователю туннеля на VPS разрешить ещё `PermitListen 127.0.0.1:18082`.
- Офисный ПК: свой скрипт автозапуска по образцу `deploy/windows/office-autostart.ps1` (приложение + свой туннель). Запуск вручную — `run.bat` / `start.ps1` по образцу дашборда.

Пошаговые инструкции — в README репозитория.

**Размещение потом** — Ubuntu-сервер: `deploy/install.sh` по образцу дашборда (служба systemd, Caddy, ежедневная копия базы).
